= install

Resolver-style `install` front door across package managers. Resolves, explains and asks; never guesses silently.

link:https://github.com/openshellorg/install/issues[Report Bug] |
link:https://github.com/openshellorg/install/issues[Request Feature] |
link:https://docs.opensh.org/tools/install/index.html[Explore the docs]

== About The Project

Part of the OpenShellOrg command-namespace work: the shell finds commands in a hierarchical, task-shaped namespace instead of searching `PATH`.
Design seed: link:https://github.com/openshellorg/project-plans/blob/main/seeds/2026-10-26%20-%20install-resolver-cli.md[project-plans seed]. Concept page: link:https://docs.opensh.org/open-shell-org/concept-command-namespace.html[Command namespace and context requests].

Status: scaffold only.

== Usage

v0 is *read-only*: it searches and never installs.

[source,shell]
----
osh-install                          # help
osh-install search ripgrep           # winget, scoop and npm
osh-install search ripgrep --manager winget,npm
osh-install --json search ripgrep
osh-install managers                 # which managers were found
----

The binary is `osh-install` because coreutils already has an `install` command (PROVISIONAL; see the command-namespace design decisions). In the command namespace it is the `install` verb.

Exit codes: 0 results found, 1 no results, 2 usage error. A manager that isn't installed is skipped and reported.

Build and test with LDC + dub: `dub test`, `dub build`.
